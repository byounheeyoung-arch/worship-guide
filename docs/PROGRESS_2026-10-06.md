# Desktop MVP 개발 체크포인트 — 2026-10-06

기준: `reboot-2026-10`, Draft PR #2, `docs/WORK_HANDOFF.md`, Drive의 v2.0.2 / 원본 PDF / WGDB Master.

이번 작업은 요청한 **우선 밑작업**에 맞춰 하나의 테스트 가능한 Desktop 프로젝트로 통합했다. 기존 버전별 프로젝트나 새 배포 ZIP은 만들지 않았다. 아직 Windows 배포 완료 또는 552페이지 전체 검수 완료 단계는 아니다.

## 구현과 데이터 보존

- 하나의 앱·WGDB·사용자 데이터 위치. 기존 실행 명령과 BAT도 같은 앱에 연결.
- schema migration v1~v3. 기존 editor / review / 혼합 DB의 ID·WGID·메모·악보·Collection·Setlist 참조 보존, migration 전 SQLite backup, 실패 시 rollback, 미래 버전 DB 보호.
- SHA-256 원본 식별과 관리 복사본, 페이지별 작업 저장, 중단·재개, 엔진별 OCR 관측 이력.
- Song → Arrangement → Score Variant. 같은 곡의 조성별 페이지를 합치거나 없애지 않음.
- OCR 원문·후보·근거·사람 확정값 분리. 추천 제목·이전 수정 기억·미확인 Key·동명곡 선택·검수 화면 원본 미리보기.
- 제목·별칭·작사/작곡·가사·주제·분위기·흐름·성경·BPM·박자·난이도·태그 편집과 다중조건 검색.
- Collection의 특정 악보 선택, 순서·섹션·메모·저장 조건·추가 후보 조회.
- 단순 악보 PDF, 한글 표지·목차·섹션·메타데이터 guide PDF, 세트리스트와 PDF 팩. 누락된 원본을 조용히 제외하지 않고 기존 출력 파일을 보존하며 오류를 알림.
- WGDB Master 9개 탭 / 20개 seed Song / 79개 참조 행을 별도 QA DB에 가져옴. 원본 시트를 수정하지 않고 기존 메타데이터를 덮어쓰지 않음.

원본 PDF는 **552페이지의 이미지 PDF**다. 실제 검증에서 `예수 닭기흘` / `예수 닭기틀` 등 오타가 발생했고, 원본을 보고 `예수 닮기를`로 수정했다. 이 곡의 p.1 **E**, p.2 **Eb**, p.3 **C**를 하나의 Song 아래 세 개의 독립 악보로 보존했다. 인수인계의 E/F/G 예시는 설명용이며 실제 페이지 조성으로 사용하지 않았다.

단순 PDF는 20페이지, guide PDF는 43페이지로 생성했다. 선택 순서를 역순으로 구성하여 **모든 20페이지를 원본 렌더 해시와 비교**했고, 한글 표지·목차와 20개 bookmark의 도착 페이지도 확인했다. 검증용 Collection 및 잘못된 후보 주입은 별도 DB 복사본에서만 수행했다.

실제 검수 기준은 `tests/fixtures/scan20_review.json`, 통과 근거는 `docs/SCAN20_EVIDENCE.json`에 기록했다. 공개 저장소에는 악보 PDF·이미지·사용자 DB·마스터 시트 원문·개인 링크를 올리지 않았다. 자동 테스트의 합성 OCR과 실제 EasyOCR 검증을 구분했다.

전체 분석 gate는 같은 원본 SHA-256과 pipeline revision의 20페이지 E2E 통과 기록을 요구한다. 페이지 수만 채우거나 OCR 결과를 자동 승인하여 gate를 열지 않는다. 개발 QA DB의 통과 기록이 사용자의 다른 DB에 자동 복사되지는 않는다.

## 남은 작업

1. **552페이지 전체 OCR 및 검수**: 20페이지 조건은 통과했으며 대량 분석 경로가 준비됐다. 이번 체크포인트에서 나머지 532페이지 처리를 완료했다고 주장하지 않는다. 전체 분석 후에도 OCR 후보를 사람이 검수해야 한다.
2. **Windows 실제 실행 / 배포**: Linux의 실제 Tk 흐름과 Windows CI의 core / wheel 검증은 통과했다. Windows CI에서 GUI 테스트는 생략했으며, 사용자 PC의 실제 DB와 Windows GUI·설치형 패키지 검증은 아직 별도 단계다. Linux 화면에는 한국어 글꼴이 필요하다.
3. **OCR 품질**: 인쇄 Key와 코드열은 후보 근거로 사용한다. 오선의 조표 기호를 자동 판독하는 기능은 아직 없고, 제목 인식에도 오타가 있으므로 검수 단계가 필수다.

다음 작업도 같은 브랜치와 DB migration을 이어서 사용한다. PR은 Draft로 유지한다.
