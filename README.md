# Worship Guide 3.0 · Desktop / Web MVP

PDF → 텍스트 추출 / 한글·영문 OCR → 사용자 검수 → Song / Arrangement / Score Variant → 다중 조건 검색 → Collection → 원본 PDF 출력.

## 실행

Node.js 22 이상과 Python 3.10 이상을 설치합니다.

```sh
npm ci
npm test
npm run build
npm start
```

브라우저에서 `http://localhost:8765`가 열립니다. Windows는 빌드 후 `start-windows.bat`로 실행할 수 있습니다. Desktop MVP는 로컬 브라우저 앱이며 별도 설치형 EXE는 아닙니다. Vercel은 `vercel.json`을 사용해 같은 웹 앱을 배포합니다.

## 사용 순서

1. **PDF 가져오기**에서 파일과 페이지 범위를 선택합니다. 텍스트 PDF는 바로 추출하고 이미지 PDF는 Tesseract 한국어·영어 OCR을 사용합니다. 실패한 페이지는 원본을 남겨 수동 검수할 수 있습니다.
2. **검수 대기 → 열기**에서 원본과 제목·Key·가사·메타데이터를 비교하고 승인합니다. 같은 곡의 다른 Key는 **기존 곡에 연결**을 선택합니다. 여러 페이지 악보는 끝 페이지를 조정합니다.
3. **보관함**에서 제목/가사/작곡/성경, 주제, 분류, 분위기, 예배 흐름, Key, BPM, 난이도, 즐겨찾기, 검수 상태를 함께 검색합니다.
4. **악보집**을 만들고 보관함의 **악보집 +**로 버전을 추가합니다. 악보집을 여러 개 만들었다면 악보집 화면에서 원하는 악보집을 선택한 뒤 보관함으로 이동합니다. 순서를 바꾸고 **PDF 출력**합니다.
5. **백업 · 이전**에서 원본 PDF까지 포함한 전체 백업을 다운로드합니다.

## 데이터 보존

- 사용자 데이터는 코드 폴더/서버가 아니라 브라우저 IndexedDB `worship-guide`에 저장됩니다. 같은 origin에서 코드 업데이트는 데이터를 초기화하지 않습니다.
- 저장은 파일과 메타데이터를 하나의 트랜잭션에 기록합니다. 직전 상태도 `previous`로 보관합니다. 손상 또는 알 수 없는 스키마는 초기화하지 않고 오류를 표시합니다.
- 브라우저 삭제/프로필 변경/기기 변경/프리뷰 URL 변경에는 전체 백업과 복원이 필요합니다. 영구 저장 요청은 브라우저가 거절할 수 있습니다.
- 복원은 병합이며, ID 충돌 시 기존 내용을 보존하고 별도 항목을 만듭니다. PDF 원본이 다른 경우도 격리합니다.
- PDF 파일은 서버에 전송하지 않습니다. OCR 첫 실행은 언어 모델 다운로드에 인터넷이 필요합니다. 원본은 전송하지 않지만 모델 제공 서버에 접속합니다.
- 원본 없는 악보는 정보를 보존하며, PDF 출력 시 누락을 조용히 생략하지 않고 오류를 표시합니다.

## v1/v2 자료 이전

```sh
python scripts/migrate_legacy.py "기존자료.db" "이전백업.json" --asset-root "악보폴더"
```

생성 파일을 웹 **백업 · 이전**에서 불러옵니다. 두 구버전 테이블(`scores`, `score_variants`)을 모두 읽습니다. 기존 SQLite를 읽기 전용으로 열고 새 파일에만 기록합니다. 원본 경로가 없으면 나중에 검수 화면에서 PDF를 연결합니다. 원본 DB·폴더는 이전 검증 후에도 보관하세요. 구버전 추가 테이블은 변환 파일 `legacyTables`에 보존합니다.

## 범위와 제한

- Key는 별도 악보 버전 관리이며 음표 자동 이조가 아닙니다. OCR Key는 명시된 Key 텍스트만 후보로 사용합니다. 오선 조표 자동 판독은 제공하지 않습니다.
- 페이지별 초안을 만드므로 하나의 곡이 여러 페이지이면 범위를 검수해야 합니다. 목차/빈 페이지도 수동 확인 대상입니다.
- PDF 내장 뷰어가 없는 브라우저에서는 원본 미리보기가 제한될 수 있습니다.
- 대용량 PDF/OCR/전체 백업은 브라우저 메모리와 저장 공간의 영향을 받습니다. 작은 페이지 범위로 나누어 가져올 수 있고 완료 페이지는 즉시 저장됩니다.
- 기기 간 자동 동기화, 다중 사용자 서버 DB, 악보 편집/자동 이조, 설치형 EXE는 이 MVP의 범위 밖입니다.

## 개발

`web/model.js`가 데이터 규칙과 검색/검수/병합을 공유합니다. `web/storage.js`는 영구 저장, `web/pdf.js`는 PDF/OCR/출력, `scripts/migrate_legacy.py`는 이전 담당입니다. 구버전의 분리된 DB 실행 경로를 하나의 모델로 대체했습니다. 테스트는 검색 조합, 검수 이력, 관계 무결성, 백업 충돌, 구버전 양쪽 스키마와 원본 불변성을 검증합니다.
